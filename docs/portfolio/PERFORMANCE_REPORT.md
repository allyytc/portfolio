# Phase 7B — performance and technical optimization

Local audit, 2026-10-29. The original site/repository and all editable Blender sources remain untouched. No deployment, hosting/DNS change or paid service was used. A recoverable 109-file checkpoint and frozen generated baseline bundles live in `assets/checkpoints/phase7a-performance/`; original large media/model files were not duplicated for profiling.

## Measurement conditions

Baseline and optimized production builds use identical local gzip servers, installed Chrome 156 and the same Mac/ANGLE Metal Apple M5 renderer. Browser sampling uses three cold isolated contexts per viewport: desktop 1440×1000/DPR2 and phone 390×844/DPR2, with the same drag and opt-in phone controls. Lighthouse 13.6.0 uses three runs per build, mobile simulation at 412×823/DPR1.75, simulated 4× CPU slowdown and its recorded network settings. These jobs run sequentially, without regression browsers competing for resources.

Raw records, exact conditions and bundle names are under `evidence/phase7b/`: `baseline-browser.json`, `after-browser.json`, three `baseline-lighthouse-*.json` and three `after-lighthouse-*.json`. [comparison.json](evidence/phase7b/comparison.json) records medians. Browser resource bytes are encoded response bodies, not total source-tree disk size or HTTP headers. “Room ready” means the first sampled substantial model draw, not a universal interactive-readiness standard. Canvas is not represented reliably by DOM LCP, so room timing is recorded separately.

## Changes supported by the audit

- **Initial JavaScript:** the complete case-study/profile/community module now loads at the panel boundary rather than on studio landing. The native modal shell, loading announcement, close/back controls and essential navigation remain immediate. Large photos/videos remain on demand. The content module has a recovery boundary: if its script fails, the app retains close/back controls and offers the static text portfolio, working PDF and email rather than crashing the root.
- **Phone asset:** `build_compact_glb.py` derives a 2,709,380-byte phone GLB from the existing 3,260,508-byte original. Only the embedded 4096² baked JPEG is resized to 2048² using free macOS `sips`; the second 1024² texture remains intact. All 36 geometry/other buffer views, nodes, meshes, materials, accessors, UVs/normals, transforms and named interactive objects are preserved. Original GLB and editable `.blend` remain unchanged. The asset selection is stable for a page session; resizing does not download both variants. Exact structural/hash proof: [compact-model.json](evidence/phase7b/compact-model.json).
- **Rendering:** the original already had demand rendering and zero idle draws, so no idle-FPS gain is claimed. Memoizing the Canvas subtree isolates DOM tooltip updates; small tooltip motion is deduplicated. Phone render DPR is capped at 1.25; desktop retains 1.5. Optional “Lighter 3D rendering” caps DPR at 1, reduces realtime shadow-map resolution to 1024² and disables optional PCSS softening. All room objects, baked atmosphere, contact shadows, content and navigation remain. Camera bounds, default framing, printer hook and geometry are preserved.
- **Asset audit:** the detailed export has 25 nodes/meshes, nine materials, 223,451 source triangles, two textures and existing Draco/unlit extensions. It is already compressed and consolidated; no speculative geometry deletion, destructive decimation or redundant re-modeling was justified. Estimated model texture RGBA+mipmap footprint falls from 95,070,890 to 27,962,027 bytes for the phone variant. This is not total measured GPU VRAM; it excludes render targets/driver overhead. Live read-only Blender inspection did not return within the audit window; GLB binary/JSON, existing pipeline records and source hashes supplied the asset audit instead.
- **Reliability:** context loss exposes a restartable HTML fallback; invalid/missing model and corrupt embedded baked texture do not leave a white unfinished room. Required texture validation occurs before declaring the model ready. Model/decoder cache clearing covers both exports. Failed images keep their content and external links available; slow model loading does not block HTML navigation.

## Navigation, base paths and semantic delivery

Hash routes work on static hosting without server rewrite rules: `#projects`, `#projects/korbit` (and other project slugs), `#about`, `#experience`, `#skills`, `#community`, `#community/dfa`, `#events/beaverhacks2026`, `#design`, `#design/unwrap`, `#contact`, `#resume` and `#stickers`. Browser Back/Forward and refresh are tested. Internal detail views update the address without remounting normal list/detail state; browser history navigation resolves the appropriate panel. A deep-linked past project returns to a list containing its focus target. The keyboard skip link focuses Quick View without being mistaken for a route. Unknown routes show a useful notice and retain navigation.

Production URLs for models, decoder, font, PDF, media and generated text content work under the tested `/portfolio/` prefix. Playwright now starts both the dev and production audit servers when needed; the production server's cold startup/subpath check was exercised after stopping the manually started server.

`content.html` is generated from the same typed records at every build (also available in dev): full original project text, organization/event stories, skills, education, contact and shared graphics/stickers, escaped as semantic HTML with ordinary links and lazy images. A noscript link and footer link expose it without JavaScript or WebGL. No CMS, runtime data service or hand-copied second biography was added.

Open Graph fields, an existing approved room-render preview and limited Person structured data were added. Development `noindex,nofollow` remains intentional. Canonical/absolute social URLs are not invented or pointed at the original domain; these require the independently approved destination during Phase 8. Consequently the local Lighthouse SEO score remains limited by the prelaunch indexability restriction. Hash-based interactive routes are not asserted to provide separate server-rendered search pages; the static text companion provides a crawlable content surface once indexing is approved.

## Tests, reproducibility and limitations

The baseline production build and 53 existing tests passed. The full expanded 59-test suite passed; the final six technical tests additionally cover the content-script failure fallback and fallback-state contrast. A final production/static-text follow-up also passed after adding source recognition/category and CTA preservation to the text companion. A separate unmocked KO.rbit YouTube check confirmed native player playback (`currentTime=1.879426`, `paused=false`, `readyState=4`); see `live-video.json`. Local MP4 playback is covered by regression tests. The existing player module remains unchanged. Strict TypeScript/no-unused checks pass. There is no existing lint script/configuration, so a separate lint pass is not claimed. `axe-core@4.11.1` is one audit-only pinned devDependency; runtime dependencies did not change. Lighthouse is a pinned local CLI tool. See `PHASE7B_ASSETS.md` for tooling licenses/provenance.

Scripts: `serve_audit.mjs` (root + optional port), `profile_browser.mjs` (label, URL, build root), `run_lighthouse.mjs` (optional baseline/after), `summarize_performance.py`, `build_compact_glb.py`, and `audit_technical_phase7b.py`. Audits use local ports 4173/4174; this is test infrastructure, not deployment configuration. Hashed JS/CSS is served immutable, HTML no-cache and nonhashed static assets with a short cache lifetime by the local server only. Actual launch-host caching remains to be checked; no service worker or real hosting headers were installed.

The host is shared, not hardware-isolated; OS scheduling, user activity, GPU shader caches and power/thermal state can affect results. RAF frame gaps are not GPU timer-query measurements. Smooth 60Hz samples on this Mac do not prove older-phone performance. Automated accessibility results are not formal WCAG certification. Real Safari/Firefox/mobile hardware, long-session memory/thermal behavior and assistive-technology review remain Phase 8 audit items.

Before/after homepage captures and desktop/mobile UI/fallback captures are under `evidence/phase7b/` and `regression/`. They were inspected for retained room composition, texture/material appearance, original media and readable HTML. The phone export is slightly softer at miniature scale; no object or content was removed. The desktop uses the original detailed model. [preservation-checks.json](evidence/phase7b/preservation-checks.json) verifies original assets/content/player/camera sources.

The approximately 972KB raw lazy Three/model-loader chunk warning remains. Vite also reports a future native-config-loader import-extension warning from the source-backed static generator's current bundled TypeScript imports; the present build works. Neither warning is hidden or described as fixed. Unwrap verification gaps and previously blocked Devpost checks remain unchanged. Phase 8 must start with an independent final audit and require explicit owner approval before launch. Nothing is deployed.
