# Content architecture

`schema.ts` defines Project, ProjectCategory, CaseStudySection, MediaAsset, Experience, Organization, Event, DesignWork, SkillCategory, Profile and ExternalLink. This layer imports no scene objects, camera controls or React components.

`case-studies/` contains all nine complete original projects plus the partially verified Unwrap product case study. KO.rbit's approved Phase 6A data is unchanged. `catalog.ts` is the single case-study registry; `projects.ts` derives discovery metadata from it. `design-work.ts` holds 46 graphics/stickers/supporting design records backed by shared binaries. `profile.ts` contains complete original About/Education, the one professional role, contact links and six skill categories. `community.ts` contains all five organizations, three event stories, ordered photos/artwork and community overview. `experiences.ts` now holds UI selection types, with no shortened duplicate biography or role text. Unwrap source observations, existing UI captures and unresolved personal/deployment claims are explicitly distinguished.

To add a later case study, define a `Project` in a data module, register its stable content ID in `catalog.ts`, ; discovery cards derive from that registry. No 3D code changes are required. Existing 3D monitor and Quick View both open the same Projects component. Preserve original source facts, full prose, technical distinctions, captions/order and links. Do not replace absent sections with invented text.

Content blocks support paragraphs/rich emphasis, ordered/unordered lists, tags, individual media, galleries, links and expandable details. Media distinguishes images, local videos and source embeds, with accessible descriptions, captions, source references and rights status. Empty optional sections are omitted by the renderer. Keep essential contributions/outcomes visible; use disclosures only for genuinely secondary technical material.

Local image files are served relative to Vite's base URL. Original media paths, Git blobs and checksums stay in each media record/acquisition evidence. Embeds load on request; the original external demo link remains available. Never execute original website JS as a migration shortcut, import source HTML into the runtime, or use unsanitized `dangerouslySetInnerHTML`.

Source recovery and deferred work are indexed in `docs/portfolio/MIGRATION_CHECKLIST.md` and `evidence/phase6c/migration-index.json`. Scripts parse original files as inert data; all original project text and 94 unique original media files are integrated, along with two source-backed Unwrap development captures. Reconcile ambiguity/rights before later publication.

Presentation configurations distinguish software, web/UX, technical and product studies without duplicating the renderer. Section navigation derives from populated content, with measured sticky offsets. The original click-to-load VideoDemo function is unchanged; image fullscreen adds full-size/Fit for long wireframes. Design/sticker filters share one metadata registry.

Phase 6C reuses `CaseStudySections` and `ScreenshotGallery` within distinct editorial, timeline, skills, organization and event interfaces. Official source role title is preserved separately from the preferred visible label. Source media references retain local hashes and provenance. Skill/project connections require exact technology-name matches; no proficiency or fuzzy associations. Existing studio interaction IDs stay stable. Cross-links open shared project data or existing community destinations, and original external CTAs remain available. `CaseStudy.backLabel` customizes only the return label for archive/community links; the default project flow remains unchanged.
